# MVCL Benchmark Suite

Reproducible benchmark artifacts accompanying the MVCL (Multi-View Constraint Language) research study on inconsistency detection and context-dependent tolerance classification in heterogeneous collaborative multi-view modeling.

## Manuscript and Journal

This repository accompanies the manuscript prepared for **Technologies (MDPI)** (ISSN 2227-7080). It contains the machine-readable rule specifications, benchmark configuration metadata, metamodels, tolerance decision records, performance summaries, detection result summaries, schemas, scripts, and tests referenced by the manuscript.

The package is identified by `artifact_manifest.json`, which records the manuscript version and the benchmark/result values used in the submitted study. No public repository URL or DOI is embedded here because a persistent publication URL has not been supplied.

## Contents

- 30 MVCL rules: 8 syntactic, 10 structural, 12 semantic
- Five benchmark configurations: B-100, B-500, B-1000, B-TOL, B-COMP
- Three standard EMF Ecore metamodels
- Benchmark-level ground-truth/reference summaries
- Detection, performance, and tolerance result artifacts
- Context definitions and the fixed 65% tolerance decision threshold
- Generation/evaluation utilities, schemas, and automated tests

## Quick Start

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Linux/macOS
# source venv/bin/activate

pip install -r requirements.txt
pip install -e .
```

Run the artifact validation and Python-side tests:

```bash
python scripts/validate_artifacts.py
python -m pytest tests/
```

The Eclipse-side MVCL/Xtext/EVL execution path is described in `docs/usage.md`. The repository's Python utilities do not substitute for the Eclipse validation implementation.

## Tolerance Results

The tolerance layer uses a fixed operational threshold of 65%. The repository preserves ten thresholded decisions per case in `results/tolerance/raw/`; the retained records contain decisions rather than raw numerical LLM scores.

| Context | Tolerable | Non-tolerable | Accuracy | Consistency |
|---|---:|---:|---:|---:|
| Prototype | 19 | 6 | 0.760 | 0.760 |
| Production | 5 | 20 | 0.920 | 0.880 |
| Maintenance | 14 | 11 | 0.920 | 0.920 |
| Overall | 38 | 37 | 0.867 | 0.853 |

The reference labels are generated by the benchmark's policy-based tolerance oracle. They are benchmark reference decisions rather than expert-adjudicated labels.

## Context Definitions

`rules/contexts.json` records the three operational contexts used in the tolerance study, including phase, criticality, deadline, team size, and budget, together with the 65% decision threshold and the definitions of the representative run and repeated-run consistency.

## Detection Workflow

The intended implementation workflow is:

```text
Ecore Models → MVCL/Xtext scope and linking → EVL validation → Typed violations → JSON artifacts
                                             ↓
                                  Context + inconsistency
                                             ↓
                                  Tolerance realization
```

The paper uses GPT-5.6 as one downstream realization of the abstract tolerance interface; the LLM does not participate in the MVCL detection semantics.

## Reproducibility

The default Python benchmark-generator seed is `42`. Timing artifacts contain 10 measured runs after one warm-up run, and memory is sampled through the measurement procedure documented in the manuscript. Tolerance records contain 10 thresholded runs per case.

## Artifact Validation

`results/validation_checklist.json` records automated internal consistency checks over the bundled JSON artifacts. The validation script recomputes key aggregates, verifies the tolerance files, checks the context definitions, and validates the three Ecore files as XML.
